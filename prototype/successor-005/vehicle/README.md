# vehicle/ — S5 relcheck acceptance vehicle

Cross-release pre-flight over frozen r1/r2/r3 (S5-DESIGN §2, with the
§2.2 strengthening; the bare checker is UNFIT and is not built).

## Layout + authorship split (R-D)

Release (shipped, lane re-runs from byte-verified copies):

- `relcheck/` — the advertised bundle: `MANIFEST.json` + `pins.json`
  (both GENERATED by `make_vehicle_pins.py`, deterministic) +
  `bin/relcheck.py` (the step program; the only hand-written bundle
  file). Steps (R-C): identity, suite-r1, suite-r2, suite-r3,
  compat, package.
- `verdict_relcheck.py` — the §2.3 checker (builder-written, frozen
  at prereg, verifier re-runs). Independent parsers/extractors/rule.
- `make_vehicle_pins.py` — deterministic build tool that cuts pins +
  manifest from pristine frozen bytes (3 generation gates; re-run
  yields byte-identical outputs).
- `relcheck-pins.json` — full pins incl. bundle sha + frozen paths
  (GENERATED; the checker's `<pins>` anchor).
- `README.md` — this file.

Throwaway readiness aids (R-D disclosed, NOT release code, never
shipped as release behavior):

- `s5-readiness-check.py` — S5-A10 readiness orchestrator (host run
  + direct baseline + checker × 2 + expense gate + hygiene scan +
  frozen both-ends + claims diff).
- `direct_relcheck.py` — S5-A10 direct baseline runner (identical
  bundle bytes, no host). The U-execute direct arm (§5 make-style
  runner) is lane-owned; this script is readiness scaffolding only.

## Execution model (S5 honesty posture)

Bundle programs ride per-run `inputs` (the host stages them into
each step scratch; every input byte is hashed in `proc_begin`);
pins ride the staged bundle (P8-verified pre/post-run). The join is
checker-side: `input_hashes[relcheck.py]` must equal the bundle
program pin, `input_hashes[pins.json]` the pins pin, step-output
`pins_sha256` the pins pin — any skew is `RELCHECK-INVALID`.

## Frozen roots + placement

Frozen roots come from `relcheck-pins.json` (absolute paths on the
pinned machine). Suite children run on scratch copies (never
frozen); `--help`-style execution against frozen bytes is never
used (surface extraction is read-only AST). Readiness roots are
throwaway `/tmp` dirs (disclosed): R3's own record shows in-tree
s004 atomicity at 625.6 s wall, past the §1.1 600 s per-step
ceiling on this 9P mount, so in-tree vehicle roots cannot satisfy
the ceiling; U-execute placement is the lane's call (§7.1).
