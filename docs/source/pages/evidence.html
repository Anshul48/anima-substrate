Evidence, and where it stops.

One validated prototype for one kind of job: fix a bug, judged by hidden tests. Everything below is a recorded run you can open and a record you can check.

The nine jobs

Each job is a real bug from a well-known open-source Python library, with a plain-English description. A Muse Code worker tries first (the first rung, in the recorded runs). A hidden checker, tests the agent does not see and cannot edit, judges the result. If the checker says no, the next helper, Claude Sonnet, gets the job plus the one failing line.

This is a trimmed copy of the real log (full file):

REAL cachetools-unbound-keyword rung=0 pool=laptop-muse said-done=yes gate=FAIL rule=target-tests
REAL cachetools-unbound-keyword rung=1 pool=claude-sonnet said-done=yes gate=PASS rule=-
REAL click-short-help-abbrev rung=0 pool=laptop-muse said-done=yes gate=FAIL rule=target-tests
REAL click-short-help-abbrev rung=1 pool=claude-sonnet said-done=yes gate=PASS rule=-

rung=0 is the Muse Code worker (laptop-muse is the name of its pool in the log), rung=1 is Claude Sonnet. said-done=yes means the agent claimed it was finished. gate=FAIL means the hidden checker disagreed, and rule=target-tests means the tests written for that bug failed.

What the checker saw in the second case: the agent’s fix cut a help text in the wrong place.

E   AssertionError: assert 'Pick a fruit. 3...' == 'Pick a fruit.'

The agent had not noticed. The checker did, and the next helper was handed the task plus that one line. (Full checker output)

The record

Each decision in the run is one line in a file, and each line carries a fingerprint (a tamper-evident seal) of the line before it. Change anything and the break shows up. You can check it in your browser or in a terminal.

Honest limits

  • This is a validated prototype for one kind of job: fix a bug, judged by hidden tests. It is not a general job scheduler.
  • Nine jobs, one run. That is a worked example, not a statistic.
  • The second helper was told the failing line, so it was an informed retry, not a blind one.
  • The libraries are public, so the agents may have seen similar fixes before.
  • We make no claim about long runs, or about leaving it alone while you are away. That is untested.
  • The seal shows the record was not changed afterwards. It cannot show that the run itself was honest, and the check does not re-run the nine jobs.

  • The checker’s code is not yet in this repository as a command you can re-run on the nine jobs, so only the record of the run can be re-checked from here.

  • Everything on this site is our own measurement. No outside party has verified it.
