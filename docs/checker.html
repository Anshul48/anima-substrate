Features / Hidden checker

A checker the agent cannot see Prototype

Tests the agent cannot see or edit decide whether an answer is right. A wrong "done" is caught, and the next helper is given the task plus the one failing line.

Prototype. Something runs, in a limited form. The limits are listed on this page.

What it does

When an agent says it is finished, ANIMA does not take its word for it. Hidden tests, which the agent cannot see or edit, judge the answer. If the answer is wrong, the next helper gets the task plus the one failing line: a Muse Code worker first (in the recorded runs), then Claude Sonnet, then Codex.

See it

Two lines from the recorded nine-job run. Each line is one attempt, with the checker's verdict as recorded:

cachetools-unbound-keyword rung=0 pool=laptop-muse said-done=yes gate=FAIL rule=target-tests
cachetools-unbound-keyword rung=1 pool=claude-sonnet said-done=yes gate=PASS rule=-

The agent said done and was wrong. The checker said no, the next helper fixed it, and all nine jobs ended verified. The full log is on the evidence page.

What exists today

Validated on one kind of job (fix a bug, judged by hidden tests): in a recorded run of nine real jobs, seven answers were right the first time and two wrong "done" answers were caught. The checker's code ships in this repository, and it judged live fresh-clone runs that ended VERDICT PASS.

Limits

One kind of job. The nine-job run used our earlier driver, so only the record of that run can be re-checked from here.

What it will do

The same hidden tests judge every run, whichever coding tool runs it.

How to check it
