How it works, in plain words.

ANIMA sits between you and the coding tool you already use. It does not replace that tool. It adds a memory, rules, a checker and a screen around it. What follows is the design. The badge on each step says what exists today.

What happens to one task

  1. You give it a task Not built yet

    By typing, or by speaking, with speech turned into text on your own computer.

  2. It looks in the memory Prototype

    The design: ANIMA asks whether something like this was fixed or decided before, and the notes come back with a pointer to where each came from. The recall command is not built yet.

  3. Your harness does the work Not built yet Not built yet

    ANIMA hands the task and the notes to Muse Code, Claude Code or Codex. The rules apply while the agent works: no secrets read, nothing pushed.

  4. A hidden checker judges the answer Prototype Prototype

    Tests the agent cannot see or edit decide. If the answer is wrong, the next helper gets the task plus the one failing line: a Muse Code worker first (in the recorded runs), then Claude Sonnet, then Codex.

  5. Every decision is recorded and drawn Working today Not built yet

    Each decision is one line in a log, and each line carries a fingerprint of the line before it, so an edit shows. The state tree screen draws that log: mission, tasks, attempts.

What ANIMA is not

  • It is not a model. It makes the tools and models you already have easier to trust and to see.
  • It is not a general job scheduler. What was validated is one kind of job: fix a bug, judged by hidden tests.
  • It does not claim that agents can work for hours unattended. That is untested.
