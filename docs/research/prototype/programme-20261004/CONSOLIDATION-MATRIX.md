## Top gaps (s006 vs accepted functionality)

1. **Missing SST leg (ABSENT).** The entire snapshot-verified search path — `sst_leg.py`, `vendor/` 54-file snapshot, `verify_snapshot.py`, `make_snapshot_manifest.py` — is absent; callers get a loud `RuntimeError`. This also takes down `run_demo` and the S1–S6 accept re-derivation in-tree. Root cause is structural: venv+pydantic vs stdlib-only. Any consolidation that needs the integrated path (R10) must either relax stdlib-only or vendor a stdlib-compatible SST surface — neither exists today.
2. **S6-only-smoke procedure coverage (PARTIAL, explicitly unverified).** `procedure.py` is byte-identical to the accepted s005 bytes, but the 57-test qualification (interruption L1–L5 incl. real SIGKILL loops, accountability, recovery/change, wording audit) was not re-run; s006 cover is 3 smoke tests. Byte-identity is not behavior evidence after the surrounding tree changed (`api.open_run` now restores authorities; `recover.py` extended). LIMITS-15 says this plainly.
3. **Kill-matrix / successor-suite cover not carried (PARTIAL).** `test_atomicity` 39/39 and `test_successor` 17/17 were dropped (SST imports). The atomic-write guarantee and the every-boundary kill matrices therefore have no direct evidence in s006 — only indirect cover via quarantine/J1/CC3 kill legs. Same byte-identity-without-behavior-evidence caveat as (2), for the R11 core the tree claims to repair.
4. **H2 lane-task routing absent (ABSENT, never merged).** `task_json` / `lane_override` / derived routing exist only in the frozen experimental H2-lane; the successor line (s004→s005→s006) never picked them up. Consolidation must decide: adopt (needs merge + re-qualification against the new tree) or leave frozen.
5. **Vehicle / readiness not re-run (ABSENT).** The relcheck usefulness vehicle and READINESS-PASS exist only in s005. Needed only if the consolidated package claims usefulness/readiness; otherwise stays frozen with s005.
