Features / Your harness

Works inside your harness Working today

ANIMA works inside the coding tool you already use (the harness): Muse Code first, then Claude Code, then Codex.

Working today. You can check it yourself: the command is under “How to check it”.

What it does

A harness is the coding tool an agent runs inside. You should not have to switch tools to get memory, rules and a checker. ANIMA wraps the tool you already have: it hands over the task, applies the rules while the agent works, runs the same hidden checker on the result, and records the decision. The same task can go to a different harness by changing one word.

Muse Code first

The first harness ANIMA is built for, and the first rung of its ladder.

In both recorded runs (nine jobs each) the first rung of the ladder was a Muse Code worker. Muse Code was also our main headless worker tool while we built this project: 670 recorded jobs on two machines, 619 finished, about 170 hours of summed worker time, from 1 to 4 November 2026.

These are counts from our own job records. We make no claim about cost or speed differences between Muse Code, Claude Code and Codex. The plug-in itself is a separate part, and its state is the badge on the harness page.

In order

1. Muse Code

The first harness. Muse Code runs the task and ANIMA wraps it with the hidden checker and the rules.

Run it Working today

anima run --task tiny-bug --harness muse

2. Claude Code

The second harness. The same task, sent to Claude Code, judged by the same hidden checker.

What exists today

The Muse Code adapter runs one small bug task end to end: the worker fixes, the hidden checker judges, the record seals. Fresh-clone runs ended VERDICT PASS.

Limits

Tiny task only. The tool must already be installed and logged in. The Claude Code and Codex adapters ship, but only Muse Code has a live pass in the merged tree.
